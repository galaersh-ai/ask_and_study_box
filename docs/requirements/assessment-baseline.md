# Черновик требований третьей очереди: Assessment

**Версия:** 0.1

**Дата:** 14 сентября 2026 г.

**Статус:** предварительный черновик. Не задаёт требований для разработки.
Состав и критерии утверждаются владельцем на PH-13 до начала реализации PH-14.

## Подтверждённая граница

- Assessment включён в план отдельной очередью после Learning Studio.
- Вопросы самопроверки PH-11 не передают ответ системе, не оцениваются и не
  создают попыток, баллов или записей прогресса.
- Реализация Assessment начинается только после отдельного решения владельца
  на PH-13.

## Предлагаемый состав для обсуждения

Ниже перечислены кандидаты, а не принятые требования.

| ID | Кандидат требования |
|---|---|
| FR-A-001 | Автор создаёт оценочное задание из зафиксированного `KnowledgeSnapshot`; вопрос, критерий и объяснение связаны с Fact и Evidence. |
| FR-A-002 | Задание хранит тип вопроса, ожидаемый ответ или рубрику, допустимый способ проверки и версию. |
| FR-A-003 | Начатое оценивание создаёт отдельную попытку; ответы и результаты не смешиваются с данными самопроверки Learning Studio. |
| FR-A-004 | Проверка возвращает результат по утверждённой шкале либо `needs_review`. Ошибка модели или неоднозначность не превращается в условный балл. |
| FR-A-005 | Автор может проверить, изменить или отменить результат; решение версионируется и аудируется. |
| FR-A-006 | Читатель видит только разрешённые ему задания, собственные результаты и подтверждённые объяснения. |
| NFR-A-001 | Assessment не входит в Knowledge Core и не меняет факты или Evidence. Предлагаемая модульная граница описана в ADR-012. |
| NFR-A-002 | Обычные тесты выполняются без сети и реальной LLM; правила и провайдеры оценивания имеют контрактные тесты. |
| NFR-A-003 | Попытка хранит версии задания, рубрики, snapshot, промпта, модели и настроек проверки. |

## Предлагаемые критерии приёмки

| ID | Кандидат проверяемого результата |
|---|---|
| AC-A-001 | Результат можно проследить до версии вопроса, критерия, Fact и Evidence. |
| AC-A-002 | Техническая ошибка и неоднозначный ответ дают `needs_review`, а не выдуманный балл. |
| AC-A-003 | Изменение автором результата сохраняет исходный результат и запись решения в аудите. |
| AC-A-004 | Данные попыток не создаются при прохождении самопроверки PH-11. |
| AC-A-005 | Модульные и контрактные тесты подтверждают отсутствие импорта Assessment из Knowledge Core и Learning Studio. |

## Решить на PH-13 до реализации

- виды оценочных заданий и допустимые форматы ответов;
- кто назначает оценивание и кто имеет право его проходить;
- шкала, порог прохождения и правила повторных попыток;
- автоматические, LLM- и экспертные способы проверки;
- когда обязателен `needs_review` и кто принимает итоговое решение;
- сроки хранения ответов, попыток и результатов;
- видимость результатов для читателя и автора;
- необходимость групповых отчётов;
- персональные данные, экспорт и удаление результатов;
- входит ли первая реализация целиком в PH-14–PH-15 или этапы нужно изменить.

## Пока за границей

- адаптивная траектория обучения;
- интервальные повторения;
- долгосрочный профиль прогресса;
- рекомендации следующих материалов по результатам оценивания;
- интеграция с LMS и внешним журналом оценок.
