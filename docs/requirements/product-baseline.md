# Базовые требования Knowledge Box

**Версия:** 0.2

**Дата:** 14 сентября 2026 г.

**Предыдущая версия:** [`archive/product-baseline-v0.1.md`](archive/product-baseline-v0.1.md)

**Источник:** решения, согласованные в диалоге Codex
`01a0685a-89b8-7d33-882a-3851eb378a6c` и сведённые в концепции Knowledge Box
v0.3, и решения владельца продукта от 14 сентября 2026 г. Документ переносит
минимально необходимый контекст в репозиторий; доступ к исходному диалогу
не нужен для понимания границы MVP.

## Пользователи и роли

| Роль | Что делает в MVP |
|---|---|
| Автор | Создаёт и администрирует проект — учебный курс или другую базу знаний. Создаёт проект из предметного пакета, загружает и удаляет документы, проверяет спорные результаты и эталонный набор вопросов, управляет допуском учеников. В MVP также выполняет обязанности администратора установки |
| Ученик | Задаёт вопросы и открывает цитаты в проектах, к которым допущен. Не загружает, не удаляет и не проверяет материалы |

## Функциональные требования

| ID | Требование |
|---|---|
| FR-001 | Автор создаёт проект из валидного готового предметного пакета. |
| FR-002 | Система загружает документы PDF, DOCX, Markdown и таблицы (XLSX, CSV), сохраняя исходник и происхождение. |
| FR-003 | Изменение источника создаёт новую версию, не перезаписывая прежнюю. |
| FR-004 | Система создаёт Entity, Fact, Relation и Evidence с координатами и версией источника. |
| FR-005 | Спорный результат попадает в очередь review; решение автора сохраняется и аудируется. Критерии спорности определяются до начала PH-03. |
| FR-006 | Поиск объединяет минимум полнотекстовый и векторный сигналы; графовый сигнал включается только после измерительного spike. |
| FR-007 | Q&A строится по фактам Knowledge Core. Каждое существенное утверждение ответа ссылается на Fact и его Evidence — фрагменты исходных текстов с версией и координатами. При нехватке данных система явно отказывается отвечать. |
| FR-008 | Общие use cases доступны через API, MCP и CLI; минимальный Web UI не содержит отдельной бизнес-логики. |
| FR-009 | Автор видит состояние заданий, может безопасно остановить или повторить работу и получить отчёт. |
| FR-010 | Система экспортирует ответ, цитаты, версии и lineage в документированном формате. |
| FR-011 | Доступ к проекту определяется ролью: автор или ученик. Ученик видит только проекты, к которым допущен. |
| FR-012 | Автор удаляет ошибочно загруженный документ со всеми версиями. Производные данные удаляются или отзываются, событие записывается в аудит без содержимого документа (ADR-011). |

## Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-001 | Новый предметный пакет подключается без изменения модулей ядра. |
| NFR-002 | Повторный запуск на том же snapshot, конфигурации, версиях и кэше воспроизводим. Если источник снимка удалён, повтор завершается явной ошибкой, а не другим ответом. |
| NFR-003 | Конкретные LLM, embeddings, хранилища и индексы подключаются через порты и контрактные тесты. |
| NFR-004 | Runtime MVP использует облачный инференс модели, у которой есть проверяемый путь локального развёртывания. Целевое оборудование для локальной модели выбирается до начала PH-08. |
| NFR-005 | Обычный тестовый набор выполняется без сети и без реальной LLM. |
| NFR-006 | Измеримые пороги качества, задержки и ресурсов утверждаются до приёмки PH-04 и PH-08. Эталонный набор вопросов готовит агент, до использования его проверяет человек. |
| NFR-007 | Архитектурные документы, требования, промпты и настройки версионируются вместе с кодом. |
| NFR-008 | Документы, вопросы, ответы и интерфейс MVP — на русском языке. |
| NFR-009 | Расчётная нагрузка: 100–200 документов на курс, файл до 50 МБ, небольшое число одновременных учеников. Точные границы (курсы, объём хранилища, одновременные пользователи, задержка) фиксируются в ADR-008 при выборе базового хранилища на PH-00. |

## Безопасность и эксплуатация

| ID | Требование |
|---|---|
| SEC-001 | Секреты не хранятся в Git, логах, ошибках, кэше и аудите. |
| SEC-002 | Доступ проверяется на уровне проекта до retrieval и экспорта. |
| SEC-003 | Документы считаются недоверенным вводом; инструкции из них не могут менять системную политику. |
| SEC-004 | Тип, размер и путь загружаемого файла валидируются до обработки. Предельный размер задаётся настройкой, значение по умолчанию — 50 МБ. |
| OPS-001 | Доступны health/readiness, структурированные журналы и аудит происхождения результата. |
| OPS-002 | Backup/restore и offline replay проверяются на практике до приёмки MVP. |

## Критерии приёмки MVP

| ID | Проверяемый результат |
|---|---|
| AC-001 | Пакеты «Синтетическая компания» и «Курс по AI-агентам» проходят один цикл без изменения ядра. |
| AC-002 | Повторный ingest неизменённого файла не создаёт дубликат; изменённый файл создаёт новую версию. |
| AC-003 | Из каждой показанной цитаты можно открыть факт, точный источник, версию и координаты. |
| AC-004 | Ответ без достаточного Evidence возвращает явное ограничение, а не выдуманный факт. |
| AC-005 | Stub, внешний и локальный провайдеры проходят один набор контрактных тестов. |
| AC-006 | Unit, contract и основные integration tests проходят при заблокированной сети. |
| AC-007 | Экспорт содержит snapshot, версии schema/prompt/model/index/config и ссылки на Evidence. |
| AC-008 | Backup восстанавливается в чистой среде, после чего контрольный Q&A-сценарий повторяется. |
| AC-009 | После удаления документа его фрагменты не выдаются в поиске, Q&A и новых экспортах; факты без другого Evidence не показываются; в аудите есть запись об удалении. |
| AC-010 | Ученик не видит проекты без допуска и получает отказ при попытке загрузить, удалить документ или принять решение review. |

Численные пороги retrieval, Q&A, производительности и ресурсов пока не
утверждены. Их нельзя придумывать: они задаются версионным eval-набором и ADR
на PH-04/PH-08.

## Открытые вопросы

- критерии спорного результата для review (FR-005) — до PH-03;
- численные пороги качества и задержки (NFR-006) — PH-04 и PH-08;
- целевое оборудование локальной модели (NFR-004) — до PH-08;
- срок хранения резервных копий, в которых остаётся удалённый документ (ADR-011).

## За границей MVP

- проектирование схемы предметной области внутри установленной коробки;
- Learning Studio и генерация учебных материалов — вторая очередь, требования
  в [`learning-studio-baseline.md`](learning-studio-baseline.md);
- Assessment, проверка знаний, адаптивное обучение и учёт прогресса — следующие
  очереди;
- юридический корпус или юридические советы;
- интернет-ingest;
- автономное удаление или «забывание» знаний (ручное удаление документа
  автором входит в MVP, FR-012);
- языки, кроме русского;
- микросервисы без измеренной необходимости.
