# Базовые требования Knowledge Box

**Версия:** 0.1

**Источник:** решения, согласованные в диалоге Codex
`01a0685a-89b8-7d33-882a-3851eb378a6c` и сведённые в концепции Knowledge Box
v0.3. Этот документ переносит минимально необходимый контекст в репозиторий;
доступ к исходному диалогу не нужен для понимания границы MVP.

## Функциональные требования

| ID | Требование |
|---|---|
| FR-001 | Пользователь создаёт проект из валидного готового предметного пакета. |
| FR-002 | Система загружает разрешённые документы и структурированные данные, сохраняя исходник и происхождение. |
| FR-003 | Изменение источника создаёт новую версию, не перезаписывая прежнюю. |
| FR-004 | Система создаёт Entity, Fact, Relation и Evidence с координатами и версией источника. |
| FR-005 | Спорный результат попадает в очередь review; решение эксперта сохраняется и аудируется. |
| FR-006 | Поиск объединяет минимум полнотекстовый и векторный сигналы; графовый сигнал включается только после измерительного spike. |
| FR-007 | Q&A связывает каждое существенное утверждение с Evidence либо явно отказывается отвечать при нехватке данных. |
| FR-008 | Общие use cases доступны через API и MCP; минимальный Web UI не содержит отдельной бизнес-логики. |
| FR-009 | Пользователь видит состояние заданий, может безопасно остановить/повторить работу и получить отчёт. |
| FR-010 | Система экспортирует ответ, цитаты, версии и lineage в документированном формате. |

## Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-001 | Новый предметный пакет подключается без изменения модулей ядра. |
| NFR-002 | Повторный запуск на том же snapshot, конфигурации, версиях и кэше воспроизводим. |
| NFR-003 | Конкретные LLM, embeddings, хранилища и индексы подключаются через порты и контрактные тесты. |
| NFR-004 | Runtime MVP допускает внешний инференс модели, для которой существует проверяемый путь локального развёртывания. |
| NFR-005 | Обычный тестовый набор выполняется без сети и без реальной LLM. |
| NFR-006 | Измеримые пороги качества, задержки и ресурсов утверждаются до приёмки PH-04/PH-08. |
| NFR-007 | Архитектурные документы, требования, промпты и настройки версионируются вместе с кодом. |

## Безопасность и эксплуатация

| ID | Требование |
|---|---|
| SEC-001 | Секреты не хранятся в Git, логах, ошибках, кэше и аудите. |
| SEC-002 | Доступ проверяется на уровне проекта до retrieval и экспорта. |
| SEC-003 | Документы считаются недоверенным вводом; инструкции из них не могут менять системную политику. |
| SEC-004 | Тип, размер и путь загружаемого файла валидируются до обработки. |
| OPS-001 | Доступны health/readiness, структурированные журналы и аудит происхождения результата. |
| OPS-002 | Backup/restore и offline replay проверяются на практике до приёмки MVP. |

## Критерии приёмки MVP

| ID | Проверяемый результат |
|---|---|
| AC-001 | Пакеты «Синтетическая компания» и «Курс по AI-агентам» проходят один цикл без изменения ядра. |
| AC-002 | Повторный ingest неизменённого файла не создаёт дубликат; изменённый файл создаёт новую версию. |
| AC-003 | Из каждой показанной цитаты можно открыть точный источник, версию и координаты. |
| AC-004 | Ответ без достаточного Evidence возвращает явное ограничение, а не выдуманный факт. |
| AC-005 | Stub, внешний и локальный провайдеры проходят один набор контрактных тестов. |
| AC-006 | Unit, contract и основные integration tests проходят при заблокированной сети. |
| AC-007 | Экспорт содержит snapshot, версии schema/prompt/model/index/config и ссылки на Evidence. |
| AC-008 | Backup восстанавливается в чистой среде, после чего контрольный Q&A-сценарий повторяется. |

Численные пороги retrieval, Q&A, производительности и ресурсов пока не
утверждены. Их нельзя придумывать: они задаются версионным eval-набором и ADR
на PH-04/PH-08.

## За границей MVP

- проектирование схемы предметной области внутри установленной коробки;
- Learning Studio и генерация учебных материалов;
- Assessment, проверка знаний и адаптивное обучение;
- юридический корпус или юридические советы;
- интернет-ingest;
- автономное удаление или «забывание» знаний;
- микросервисы без измеренной необходимости.
