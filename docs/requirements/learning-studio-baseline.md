# Требования второй очереди: Learning Studio

**Версия:** 0.1

**Дата:** 14 сентября 2026 г.

**Статус:** черновик. Утверждается до начала PH-09; до приёмки MVP задаёт
только ограничения на проектирование ядра (ADR-010).

## Цель

Преподаватель получает учебные материалы по курсу, собранные из проверенной базы
знаний, проверяет их и публикует ученикам. Каждое утверждение материала можно
проследить до факта и фрагмента исходного документа.

Вторая очередь начинается сразу после приёмки MVP (PH-08). Роли те же, что
в [`product-baseline.md`](product-baseline.md): преподаватель и ученик.

## Функциональные требования

| ID | Требование |
|---|---|
| FR-L-001 | Материал создаётся только из зафиксированного `KnowledgeSnapshot` через публичный контракт Knowledge Core. |
| FR-L-002 | Виды материалов: конспект темы, карточки для самостоятельного повторения, мини-курс — упорядоченный набор тем с конспектами. Состав подтверждается до PH-09. |
| FR-L-003 | Каждое существенное утверждение материала ссылается на Fact и Evidence. Утверждение без Evidence в материал не попадает. |
| FR-L-004 | Сгенерированный материал остаётся черновиком до проверки преподавателем. Ученик видит только опубликованные материалы. |
| FR-L-005 | Преподаватель правит, отклоняет и публикует материал. Каждое действие создаёт версию материала и запись в аудите. |
| FR-L-006 | Новая версия документа или новый снимок знаний помечает зависимые материалы как устаревшие. Перегенерация запускается действием преподавателя. |
| FR-L-007 | Удаление документа снимает с публикации материалы, которые на него ссылаются, до решения преподавателя. |
| FR-L-008 | Материал хранит версии snapshot, промпта, модели и настроек, по которым создан. |
| FR-L-009 | Материалы доступны через API, MCP и Web UI с теми же проверками доступа, что в MVP. |
| FR-L-010 | Материал экспортируется в Markdown с цитатами и ссылками на источники. |

## Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-L-001 | Learning Studio — отдельный модуль. Модули ядра его не импортируют и не меняются ради него. |
| NFR-L-002 | Генерация идёт фоновым заданием и не блокирует Q&A учеников. |
| NFR-L-003 | Материалы и интерфейс — на русском языке. |
| NFR-L-004 | Тестовый набор выполняется без сети и без реальной LLM, как в MVP. |
| NFR-L-005 | Пороги качества материалов задаются версионным eval-набором, который готовит агент и проверяет человек. |

## Критерии приёмки

| ID | Проверяемый результат |
|---|---|
| AC-L-001 | На пакете «Курс по AI-агентам» преподаватель создаёт конспект и карточки, проверяет и публикует; ученик видит материал и открывает цитату до источника. |
| AC-L-002 | Материал с утверждением без Evidence не проходит проверку и не публикуется. |
| AC-L-003 | После новой версии документа зависимый материал помечен устаревшим; после удаления документа — снят с публикации. |
| AC-L-004 | Модуль подключается без изменения модулей ядра; `import-linter` это подтверждает. |
| AC-L-005 | Ученик не видит черновики и материалы курсов без допуска. |

## За границей второй очереди

- Assessment: тесты, критерии, попытки и оценки;
- адаптивное обучение;
- учёт прогресса учеников и отчёты преподавателю;
- выгрузка в LMS (SCORM и аналоги);
- юридический пакет и студия предметной области.

## Открытые вопросы

- структура мини-курса: только порядок тем или ещё цели и пререквизиты;
- нужны ли карточкам интервальные повторения (это уже учёт прогресса);
- показывать ли ученику Q&A и материалы в одном интерфейсе;
- пороги качества материалов и состав eval-набора.
