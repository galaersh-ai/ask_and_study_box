# Требования второй очереди: Learning Studio

**Версия:** 0.4

**Дата:** 14 сентября 2026 г.

**Предыдущая версия:**
[`archive/learning-studio-baseline-v0.3.md`](archive/learning-studio-baseline-v0.3.md)

**Статус:** черновик. Утверждается до начала PH-09. Ограничения на проектирование
ядра становятся обязательными только после принятия ADR-010.

## Цель

Автор получает учебные материалы по курсу, собранные из проверенной базы
знаний, проверяет их и публикует читателям. Каждое утверждение материала можно
проследить до факта и фрагмента исходного документа.

Вторая очередь начинается сразу после приёмки MVP (PH-08). Роли те же, что
в [`product-baseline.md`](product-baseline.md): автор и читатель.

## Функциональные требования

| ID | Требование |
|---|---|
| FR-L-001 | Материал создаётся только из зафиксированного `KnowledgeSnapshot` через публичный контракт Knowledge Core. |
| FR-L-002 | Виды материалов: конспект темы, карточки для самостоятельного повторения, мини-курс — упорядоченный набор тем с конспектами. Состав подтверждается до PH-09. |
| FR-L-003 | Каждое существенное утверждение материала ссылается на Fact и Evidence. Утверждение без Evidence в материал не попадает. |
| FR-L-004 | Сгенерированный материал остаётся черновиком до проверки автором. Читатель видит только опубликованные материалы. |
| FR-L-005 | Автор правит, отклоняет и публикует материал. Каждое действие создаёт версию материала и запись в аудите. |
| FR-L-006 | Новая версия документа или новый снимок знаний помечает зависимые материалы как устаревшие. Перегенерация запускается действием автора. |
| FR-L-007 | Удаление документа снимает с публикации материалы, которые на него ссылаются, до решения автора. |
| FR-L-008 | Материал хранит версии snapshot, промпта, модели и настроек, по которым создан. |
| FR-L-009 | Материалы доступны через API, MCP и Web UI с теми же проверками доступа, что в MVP. |
| FR-L-010 | Материал экспортируется в Markdown с цитатами и ссылками на источники. |
| FR-L-011 | До публикации система заранее формирует полный пакет материала: цели, структуру, основной текст, сценарий представления, задания или вопросы, Evidence-ссылки и все необходимые медиа. Незавершённая обязательная медиа-заготовка блокирует публикацию. Запрос читателя не запускает генерацию обязательного содержимого опубликованного материала. |
| FR-L-012 | Материал может содержать вопросы для самопроверки. Читатель обдумывает ответ и открывает подготовленные автором эталонный ответ и пояснение с Evidence. Система не выставляет баллы, не оценивает ответ и не хранит ответы, попытки или прогресс. |

## Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-L-001 | Learning Studio — отдельный модуль. Модули ядра его не импортируют. Изменение публичного контракта ядра требует самостоятельного требования ядра и не может обосновываться только потребностью Learning Studio. |
| NFR-L-002 | Генерация идёт фоновым заданием и не блокирует Q&A читателей. |
| NFR-L-003 | Материалы и интерфейс — на русском языке. |
| NFR-L-004 | Тестовый набор выполняется без сети и без реальной LLM, как в MVP. |
| NFR-L-005 | Пороги качества материалов задаются версионным eval-набором, который готовит агент и проверяет человек. |

## Критерии приёмки

| ID | Проверяемый результат |
|---|---|
| AC-L-001 | На пакете «Курс по AI-агентам» автор создаёт конспект и карточки, проверяет и публикует; читатель видит материал и открывает цитату до источника. |
| AC-L-002 | Материал с утверждением без Evidence не проходит проверку и не публикуется. |
| AC-L-003 | После новой версии документа зависимый материал помечен устаревшим; после удаления документа — снят с публикации. |
| AC-L-004 | Модуль подключается без изменения модулей ядра; `import-linter` это подтверждает. |
| AC-L-005 | Читатель не видит черновики и материалы курсов без допуска. |
| AC-L-006 | Опубликованный материал открывается без генерации обязательного содержимого: все заявленные части пакета уже сохранены, проверены автором и связаны с версиями snapshot, промпта, модели и настроек. |
| AC-L-007 | Читатель открывает вопрос, затем эталонный ответ, пояснение и Evidence; после сценария не создаются балл, результат проверки, попытка или запись прогресса. |

## За границей второй очереди

- Assessment: автоматическая или экспертная проверка ответа, критерии, попытки,
  баллы, результаты и оценки — предварительный черновик вынесен в
  [`assessment-baseline.md`](assessment-baseline.md);
- адаптивное обучение;
- учёт прогресса читателей и отчёты автору;
- выгрузка в LMS (SCORM и аналоги);
- юридический пакет и студия предметной области.

## Открытые вопросы

- структура мини-курса: только порядок тем или ещё цели и пререквизиты;
- нужны ли карточкам интервальные повторения (это уже учёт прогресса);
- показывать ли читателю Q&A и материалы в одном интерфейсе;
- пороги качества материалов и состав eval-набора.
