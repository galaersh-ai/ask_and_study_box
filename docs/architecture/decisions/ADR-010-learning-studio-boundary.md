# Learning Studio — отдельный сценарный модуль второй очереди поверх снимка знаний

## Контекст и проблема

Репозиторий называется `ask_and_study_box`: кроме вопросов и ответов, продукт
должен учить. План 0.1 относил Learning Studio к разделу «После MVP» вместе
с юридическим пакетом и студией предметной области, без очерёдности и этапов.

14 сентября 2026 г. владелец продукта решил:

- обучающая система идёт второй очередью сразу после приёмки MVP (PH-08);
- во вторую очередь входят только учебные материалы, Assessment, адаптивное
  обучение и учёт прогресса — следующие очереди;
- пользователи — автор и читатели;
- стартовый проект — 100–200 документов;
- обязательное содержимое учебных материалов готовится заранее, проверяется
  автором и только после этого публикуется читателям.

Инвариант `AGENTS.md` запрещает добавлять Learning Studio в ядро MVP. Нужно
решить, как построить обучающую систему и что MVP обязан заложить заранее,
чтобы вторая очередь не требовала переделки ядра.

## Рассмотренные варианты

1. **Включить Learning Studio в MVP.** Нет: расширяет согласованную границу,
   откладывает первый проверяемый результат и нарушает инвариант.
2. **Отдельный сценарный модуль в том же монолите, который читает
   `KnowledgeSnapshot` через публичный контракт.** Предлагается.
3. **Отдельное приложение или сервис.** Нет: граница MVP запрещает микросервисы
   без измеренной необходимости; пришлось бы дублировать доступ, аудит и задания.
4. **Генерировать материалы напрямую из текстов документов, минуя Knowledge
   Core.** Нет: теряется связь утверждений с Fact и Evidence, не работают
   review, версии и удаление документов.

## Примеры подготовки на основе OpenMAIC

Это материалы для будущего выбора, а не принятое решение. Примеры сверены
14 сентября 2026 г. с OpenMAIC v1.0.1. В OpenMAIC есть редактируемый план курса,
course/scene DSL, слайды, квизы, интерактивные сцены, PBL, загрузка исходных
материалов, редактор и экспорт. Knowledge Box может использовать эти идеи,
не связывая Knowledge Core с приложением OpenMAIC.

### Что готовить до публикации

| Артефакт | Пример для Knowledge Box |
|---|---|
| Паспорт материала | цели, аудитория, пререквизиты, ожидаемый результат, версия `KnowledgeSnapshot` |
| Структура | темы, порядок, сцены или страницы, переходы и длительность |
| Основное содержание | конспекты, тексты сцен, заметки ведущего, карточки и выводы |
| Практика | вопросы, квизы, упражнения, PBL-сценарий и критерии выполнения |
| Представление | слайды, диаграммы, интерактивные сцены и сценарий обсуждения |
| Медиа | готовые изображения, аудио и видео; незавершённое обязательное медиа блокирует публикацию |
| Доказательность | связь каждого утверждения с Fact, Evidence и локатором источника |
| Контроль качества | отчёт проверок полноты, Evidence, языка, безопасности и решение автора |
| Поставка | версионный пакет для Web UI и экспортов Markdown, HTML или PPTX |

После публикации читатель получает уже собранный пакет. Во время работы могут
оставаться интерактивный диалог, навигация и фиксация действий, но обязательный
текст, структура, задания и медиа не должны впервые генерироваться по запросу
читателя.

### Варианты будущей интеграции

1. **Собственный формат Learning Package.** Knowledge Box хранит независимый
   пакет и использует идеи OpenMAIC только как образец. Максимальный контроль,
   но больше собственной разработки.
2. **Адаптер к OpenMAIC DSL/SDK.** Learning Studio формирует внутренний пакет,
   затем адаптер экспортирует сцены в формат OpenMAIC. Это рекомендуемый вариант
   для будущего spike: ядро остаётся независимым, а готовые renderer/editor можно
   оценить отдельно.
3. **OpenMAIC как отдельное приложение.** Knowledge Box передаёт подготовленный
   пакет через экспорт/API. Быстрый пилот, но сложнее единые роли, аудит,
   версии и эксплуатация.

До решения нужно проверить совместимость лицензий, устойчивость DSL, импорт
Evidence-ссылок, offline-экспорт, безопасность интерактивного HTML и стоимость
поддержки адаптера. Полный runtime OpenMAIC в рамках этого ADR не проверялся.

## Решение

Раздел описывает предлагаемое решение и становится обязательным только после
смены статуса ADR на `accepted`.

- Learning Studio — модуль MOD-15 `learning` в `src/knowledge_box/learning/`.
- Модуль зависит только от публичных контрактов `knowledge` (снимок знаний
  и события его изменения), `access`, `audit`, `jobs`, `exports` и порта LLM.
- Ни один модуль ядра не импортирует `learning`; правило проверяется
  `import-linter`.
- Модуль владеет своими данными: учебный материал, версия материала,
  публикация. Knowledge Core в них не пишет и о них не знает.
- Промпты лежат в `prompts/learning/<prompt_id>/vN.yaml`.
- Этапы второй очереди — PH-09…PH-11 в `development-plan.md`, требования —
  `docs/requirements/learning-studio-baseline.md`.

## Последствия

### Плюсы

- MVP сохраняет границу и сроки.
- Материалы наследуют Evidence, версии и аудит без повторной реализации.
- Модуль можно отключить или заменить, не трогая ядро.

### Минусы

- Часть контрактов ядра проектируется с запасом под потребителя, которого
  в MVP ещё нет.
- Устаревание материалов зависит от событий ядра: ошибка в событиях незаметна
  до второй очереди, если её не покрыть контрактным тестом в MVP.

### Обязательства в коде MVP

Код обучения в MVP не пишется. Заранее закладывается:

| Этап | Обязательство |
|---|---|
| PH-00 | Граф импортов `import-linter` резервирует слой сценарных модулей, которые зависят от ядра, но не наоборот |
| PH-01 | Контракт `access` описывает роли «автор» и «читатель» на уровне проекта |
| PH-03 | `KnowledgeSnapshot` — версионный публичный контракт с контрактными тестами, а не внутренняя структура `knowledge` |
| PH-03 | Ядро публикует события «новый снимок», «новая версия документа» и «документ удалён», не зная подписчиков |
| PH-06 | Задания (`jobs`) принимают долгие операции любого модуля, а не только ingest |
| PH-06 | Формат экспорта снимка документирован и пригоден как вход для генерации материалов |

### Что отложено

- Assessment, адаптивное обучение и учёт прогресса — следующие очереди, для
  них будут отдельные ADR.
- Выгрузка в LMS.

### Открытые вопросы

- состав и структура мини-курса;
- пороги качества материалов.
- собственный Learning Package, адаптер OpenMAIC или отдельное приложение;
- какие медиа обязательны для каждого вида материала. Всё обязательное медиа
  готово до публикации; заготовка допустима только для необязательного медиа,
  которое не заявлено как часть опубликованного пакета.
